# @ldd/dsh-video-frame-analyzer

这是 LDD 随内核提供的 DeepSeek Harness 插件，注册 `analyze_video`、回环地址 `/__ldd/identity` 和 `video-analysis` Skill。插件不会把原始视频发送给模型。它先验证工作区文件，再使用 LDD 固定版本的 `ffprobe` 获取媒体信息，通过固定版本的 `ffmpeg` 检测场景变化并生成有界、带时间戳的联系表，将 JPEG 联系表保存到 `ctx.attachments`，最后交给已配置且明确支持图片输入的模型。

## 工具行为

`analyze_video` 接收 `path`、`goal`、可选的 `startSeconds`／`endSeconds` 和可选精度 `low`、`balanced`、`high`。首版支持 MP4、MOV、MKV、WebM。文件必须是当前 Session 工作区内的普通非链接文件，且不超过 2 GiB。视频超过 60 分钟时，必须明确指定不超过 60 分钟的分析区间。

基础采样间隔为：30 秒以内 1 秒，30 秒至 5 分钟 3 秒，5 分钟以上 10 秒；场景切换时间戳优先保留。场景检测只处理已选择的时间范围。每张联系表最多 9 帧，每次视觉请求最多 4 张联系表／36 帧，整次分析最多 16 张联系表／144 帧；JPEG 会在有界质量档位内自适应压缩。所有 FFmpeg／ffprobe 调用均通过 Harness 的托管子进程服务。任务取消或插件卸载时，插件先停止并等待已登记的 FFmpeg 进程树完全退出，再凭所有权标记清理唯一私有临时目录。FFmpeg 即使以 0 退出，受限收集到的解码 stderr 也会写入结果的 `decodeWarnings`。

每次嵌套模型请求之前，插件先写入 `video/analysis-input`，记录准确的模型路由、system 指令、用户消息、联系表引用、采样事实和输出 token 上限；只有日志写入成功才会发起请求。包内 invariant 要求同一分析的批次编号连续，并禁止中途切换模型路由。

Harness 0.1.1 使用生成式持久化事件词表。LDD 源码构建的 Fallback 带有受审查的事件补丁；插件模块加载时也会注册同一事件，使通过完整性校验的官方注册表版本能够持久恢复该记录。候选版本不能通过持久化能力探针时不会进入可切换状态。

LDD 默认层把视觉分析路由到 `deepseek-official/deepseek-v4-flash-vision-exp`。每批先通过 `prepareCall` 一次性绑定提供方、模型、能力和最大输出，再使用同一个已绑定调用，避免能力检查与真正请求之间发生路由漂移。结果包含视频元数据、按时间排序的观察、可见文字、证据时间戳、分析覆盖区间、未覆盖区间、解码警告、所用路由和请求次数。模型流和模型返回错误格式都会受到大小限制；错误格式会变成低置信度降级观察，不会把未校验 JSON 当作正常结果。

## 配置

随包 `cordis.patch.yml` 明确配置提供方／模型、默认精度、输出与超时上限、FFmpeg／ffprobe 绝对路径、私有缓存目录、场景阈值和停进程时限。插件加载时必须存在 `LDD_IDENTITY_NONCE`；身份路由只接受回环连接，返回该 nonce 和当前进程 id，并禁止缓存。

## 模型体验

### analyze_video 工具

#### 模型会看到什么

插件挂载时，主模型会看到工具说明和参数结构；成功结果是包含有界观察和证据的 JSON，不会把联系表图片再次塞入主会话模型。

#### Token 影响

主会话承担工具结构与结构化结果的 token。分析期间，每组最多 4 张联系表会产生一次独立视觉模型请求，该组图片和固定分析指令占用辅助请求的输入预算。

#### KV Cache 影响

工具挂载会改变主会话请求前缀。每次嵌套视觉请求相互独立；目标、区间、精度、路由或联系表引用变化都会改变请求输入与缓存身份。

## 已知限制与后续工作

- 首版只报告音轨是否存在，不自动转写语音。
- 首版只接受工作区内文件；工作区外文件的一次性明确读取授权尚未接入。
- 联系表要求随包 FFmpeg 启用 `drawtext`、`concat` 和 `tile` 滤镜。
- 场景检测与间隔采样不能保证捕获所有短暂事件，因此必须向用户保留警告和未覆盖区间。
